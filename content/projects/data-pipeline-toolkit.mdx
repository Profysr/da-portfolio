## The Problem

Data engineers waste weeks building the same plumbing: config management, schema validation, retry logic, scheduling. Every team reinvents it.

## Solution

A CLI that takes a `pipeline.yaml` and handles the rest:

```yaml
# pipeline.yaml
source:
  type: postgres
  table: raw_events
transforms:
  - clean_events
  - enrich_with_users
  - aggregate_hourly
destination:
  type: clickhouse
  table: analytics.events
```

Run with:

```bash
data-pipeline sync --config pipeline.yaml --parallel 8
```

## Architecture

- **AST-based config parser** — validates YAML at parse time, catches errors before execution
- **Zero-config defaults** — sensible conventions for naming, partitioning, monitoring
- **Async worker pools** — horizontal scaling via Redis-backed task queue
- **Multi-tenant schema isolation** — each tenant gets isolated tables/views automatically

## The Reality

Your GitHub profile is the only portfolio that can't be curated. It shows:

- **Consistency:** Do you ship regularly, or in bursts?
- **Depth:** Do you fix typos, or architect features?
- **Collaboration:** Do you open PRs, review code, respond to issues?
- **Taste:** What problems do you choose to solve?

## What Hiring Managers Actually Look At

### 1. Commit Quality > Quantity

A single PR that refactors a core module with tests > 50 "fix typo" commits.

### 2. Project Ownership

- **Owner:** You created it, maintain it, respond to issues.
- **Contributor:** You added a feature, fixed a bug, improved docs.
- **Drive-by:** One-off typo fix.

Ownership signals initiative. Contribution signals collaboration. Both matter.

### 3. Technical Breadth

Commits across different domains (frontend, backend, infra, data) signal adaptability.

### 4. Communication

PR descriptions, issue discussions, code review comments — these show how you work with others.

## How to Shape Your Signal

### Pick 2-3 Projects, Go Deep

Don't spray commits across 20 repos. Pick projects you genuinely use or care about. Stay for 6+ months.

### Write Good PRs

```
## Summary
Brief description of the problem and solution.

## Changes
- Specific change 1
- Specific change 2

## Testing
- How to verify
- Screenshots (if UI)

## Related
- Link to issue
```

### Review Others' Code

It's the fastest way to learn a codebase and get noticed by maintainers.

### Document Your Thinking

If you build something, write a short post: "Why I built X, how it works, what I'd do differently."

## The 80/20

Your GitHub is a signal, not a scoreboard. Optimize for *evidence of how you think and work*, not green squares.
